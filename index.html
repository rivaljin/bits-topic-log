논문이 있어서가 아니라 질문이 있어서 주제가 된다. 주제를 연구나 자료에서 역산하지 않는다. 먼저 독자가 가질 질문이나 실제 장면을 찾고, 자료는 그 질문에 답하기 위해 나중에 찾는다. 자료가 있다는 사실만으로 독자 수요를 가정하지 않는다.

Bits with Nampy의 범위

과학 전문 블로그가 아니다. AI·기술·여행·게임·영화·음악·소비·생활정보·과학·심리·인문·문화·에세이 등 탐색. 과학·심리 후보는 절반을 넘기지 않는다. 피자 매장·사업 경험은 소재와 분리한다.

독자 유입 경로

검색형: 사람들이 이미 답을 찾고 있는 질문. 실제 질문·검색어·커뮤니티 등 구체적 출발 근거를 확인한다.
발견형: 제목이나 장면을 보면 궁금해지는 질문. 반전은 강점이지만 필수는 아니다.

운영 순서

질문·장면 발견 → 검색형·발견형 구분 → 짧은 후보 제시 → 유형별 평가 → 수요·근거·중복 확인 → 상세 기획 → 발행 후 데이터 확인

1단계: 발굴 (후보당 3줄)

질문형 가제 / 왜 끌리는지 / 출발 근거와 확인 상태. 3~5개만. 목차·이미지 기획·논문 목록은 미리 만들지 않는다.

2단계: 유형별 평가

검색형: 실제 질문 흔적·검색 의도·기존 답변의 빈틈·그 빈틈을 채울 수 있는가.
발견형: 제목만으로 끌리는가·구체적 장면·신기함 이상의 발견·공유 이유.
공통: 제목-본문 일치·차별점·과장 없이 흥미로운가·중복·근거 확인.

3단계: 상세 기획 — 입구/중심/잔상

입구: 왜 클릭·검색하는가. 중심: 본문이 무엇을 답·탐구하는가. 잔상: 읽고 무엇이 남는가.
입구만 강하면 낚시, 중심만 강하면 안 읽히고, 잔상이 없으면 소비되고 사라진다.

정직한 확인 원칙

확인 안 한 숫자는 만들지 않는다. 관심도를 검색량처럼 표현하지 않는다. 수요와 근거는 별개로 확인한다. 대중 보도와 원자료를 구분한다.
